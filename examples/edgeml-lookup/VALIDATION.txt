RULE (honesty): every number below is followed by the EXACT command that

METHOD (thermals): this is a passively-cooled laptop; sustained back-to-back
decode heat-soaks the SoC and depresses absolute tok/s. To keep the ON/OFF
comparison fair, tok/s trials are INTERLEAVED (on,off,on,off,... within one
invocation of bench_toks.sh) so both conditions share the same thermal state,
and the reported quantity is the ON/OFF median RATIO, which is robust to
throttling. Bit-exactness and the self-test are deterministic (thermal-
independent). Peak RSS is sampled 3x per condition (it is noisy on the OFF side).

WHAT CHANGED SINCE THE FIRST DROP (CPU-backend bit-exactness fix):
A downstream verifier reproduced the speed claims on a second architecture
(Linux aarch64, Neoverse-N1, gcc 12, CPU-only) but found that on the CPU backend
(-ngl 0) the spec token ids DIVERGED from the width-1 greedy baseline at draft
width >= 4 (D >= 3). Root cause (confirmed here): a wide (>=4-wide) batched decode
on the ggml CPU matmul path sums the logit dot-products in a different order than
a width-1 decode; that reordering can flip a near-tie greedy argmax. It is
floating-point non-associativity, NOT an indexing bug, and it does NOT occur on
Metal (whose reductions match width-1 at all D). The first drop's Gate 2 passed
because it was measured on Metal only. Fix: on the CPU path (n_gpu_layers == 0)
clamp the draft width to EDGEML_CPU_SAFE_D (default 2, the measured bit-exact
maximum) unless EDGEML_ALLOW_WIDE_CPU=1. This makes "spec ids == greedy ids" true
BY CONSTRUCTION on CPU. Gate 2 below is now a per-backend x per-D matrix. The
clamp has a measured speed cost on CPU (Gate 3b / Gate 4) — reported, not hidden.

 WHY THE GATE EXISTS — ungated contrast (EDGEML_MIN_SCORE=0)  [Metal]
--------------------------------------------------------------------------------
The confidence gate is the no-regression mechanism. With it DISABLED the proposer
drafts on weak/coincidental matches; on novel prose those wide batches are mostly
rejected, so wall-clock REGRESSES even though the output stays bit-exact.
cmd: EDGEML_MIN_SCORE=0 COOLDOWN=6 ... bench_toks.sh <prompt> 512 5 99
  novel      : 0.711x  REGRESSION (fails >=0.98x)   OFF 47.9089 / ON 34.0403
  repetitive : 1.583x                               OFF 32.4766 / ON 51.4084
  => disabling the gate speeds repetitive but REGRESSES novel to 0.711x; the gate
     (min_score=5) keeps repetitive at 1.514x while holding novel at 1.013x (Metal).
Default min_score chosen from a measured sweep [run b04u1477g]: min_score=4 -> novel
0.968x (FAILS); min_score=5 -> novel 0.994x (PASSES), repetitive 1.516x. min_score<=2
disables the gate. (All on Metal.)
