out: OFF peak RSS bytes : 1130954752  1170817024  1170407424
                          (1078.6 MiB) (1116.6 MiB) (1116.2 MiB)   median 1116.2 MiB
     ON  peak RSS bytes : 1175912448  1156841472  1175977984
                          (1121.4 MiB) (1103.3 MiB) (1121.5 MiB)   median 1121.4 MiB
     delta(median)     : +0.470%   (ON 1121.4 / OFF 1116.2 MiB)    <= +2%  OK
     delta(worst-case) : +3.981%   (ON-max 1121.5 / OFF-min 1078.6 MiB)
HONEST NOTE on this gate:
  * No draft model is loaded — there is no second set of weights. The proposer
    itself is a rolling-hash index of ints (a few KiB for a 512-token run).
  * The only real growth is Metal COMPUTE SCRATCH: ON submits up-to-(D+1)=9-wide
    verification batches, so the backend sizes its compute buffer to the widest
    batch; OFF only ever submits width-1. That structural delta is ~5 MiB here
    (ON median 1121.4 vs OFF median 1116.2 MiB = +0.470%).
  * Peak RSS is NOISY on the OFF side (single OFF samples ranged 1076-1171 MiB
    across all runs; ON is stable ~1121 MiB). A single OFF sample that lands low
    can therefore show up to ~+4% (worst-case pairing above, and earlier single-
    sample runs measured +4.4%). The 3-sample MEDIAN (+0.470%) is the robust
    figure and is within the +2% gate. Both the median and the worst-case are
    reported here rather than picking the favorable one.
  * This delta does NOT depend on min_score (n_outputs_max is sized by D for both
    ON and OFF); it is purely the width of the verify batch.

--------------------------------------------------------------------------------
 WHY THE GATE EXISTS — ungated contrast (EDGEML_MIN_SCORE=0)
--------------------------------------------------------------------------------
The confidence gate is the no-regression mechanism. With it DISABLED, the
proposer drafts on weak/coincidental matches; on novel prose those wide batches
are mostly rejected, so wall-clock REGRESSES even though the output stays
bit-exact. This is the regression the task asked to be reported, not hidden.

current binary, EDGEML_MIN_SCORE=0, same interleaved median-of-5 protocol:
  cmd: EDGEML_MIN_SCORE=0 COOLDOWN=6 BIN=... MODEL=... bench_toks.sh <prompt> 512 5 99
  novel      : 0.711x  REGRESSION (fails >=0.98x)   OFF 47.9089 / ON 34.0403
               accept_rate 0.0552, multiple 1.0825, draft_steps 86
  repetitive : 1.583x                               OFF 32.4766 / ON 51.4084
               accept_rate 0.5826, multiple 3.9084, draft_steps 83
  => disabling the gate speeds up repetitive (1.58x) but REGRESSES novel to 0.711x.
     The gate (min_score=5) keeps repetitive at 1.514x while lifting novel to 1.013x.

corroboration (earlier pre-gate build, run bzbapl4lr):
  novel      : 0.731x  (OFF 43.6903 / ON 31.9356; accept_rate 0.0552, multiple 1.0825)
  repetitive : 1.349x  (OFF 47.3030 / ON 63.8017; accept_rate 0.5826, multiple 3.9084)

Default min_score was chosen from a measured sweep (run b04u1477g): at
min_score=4 novel is 0.968x (FAILS the >=0.98x gate) while at min_score=5 novel
is 0.994x (PASSES) and repetitive still 1.516x. Hence the baked default of 5.
min_score<=2 disables the gate (the ungated path above).
